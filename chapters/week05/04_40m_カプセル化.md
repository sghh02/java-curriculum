# Week 5 カプセル化（フィールドを守る）

これまでフィールドは外から自由に読み書きできました。今日はフィールドを隠します。外から直接さわれないようにして、決められた窓口だけを通す形にします。これをカプセル化と呼びます。

## まず押さえること

フィールドに `private` を付けると、そのクラスの外から直接さわれなくなります。`account.balance = 999` のような書き換えができなくなります。

では、どうやって値を変えたり読んだりするのか。メソッドを窓口にします。

- 変えるとき … 専用のメソッドを通す（例: `deposit`）
- 読むとき … 値を返すメソッドを通す（例: `getBalance`）

値を読むためのメソッドをゲッターと呼びます。名前は `get` にフィールド名をつなげるのが慣習です。

なぜ隠すのか。外から勝手に書き換えられると、おかしな値が入りかねないからです。窓口を1か所に絞れば、あとでルールを足すのも楽になります。今日はまず「隠して、窓口を通す」形を作ります。

```
class Account {
    private int balance;              // 外から直接さわれない

    void deposit(int amount) { ... }  // 変える窓口
    int getBalance() { ... }          // 読む窓口
}
```

## ステップ1: 予測写経

次のお手本を1行ずつ写します。写す前に「何が表示されるか」を予測します。写し終えたら実行し、予測と合っているか確かめます。

保存先は `src/main/java/com/example/week05/04_40m_カプセル化/AccountDemo.java` にします。同じファイルに2つのクラスを書きます。

```java
public class AccountDemo {
    public static void main(String[] args) {
        Account account = new Account(1000);
        account.deposit(500);
        System.out.println(account.getBalance());
    }
}

class Account {
    private int balance;

    Account(int balance) {
        this.balance = balance;
    }

    void deposit(int amount) {
        balance = balance + amount;
    }

    int getBalance() {
        return balance;
    }
}
```

実行は `java src/main/java/com/example/week05/04_40m_カプセル化/AccountDemo.java` です。

- 実行用クラス `AccountDemo`
  - `main` で `new Account(1000)` を作る
  - `deposit(500)` を呼び、`getBalance` の結果を表示する
- `Account` クラス

  - コンストラクタ … balance を受け取り初期化
  - `deposit(amount)` … balance に amount を足す
  - `getBalance()` … balance を返す
