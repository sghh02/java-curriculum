# Week 6 抽象クラス（中身のないメソッドで実装を強制する）

オーバーライドの続きです。前回は、子が親のメソッドを書き直しました。今回は、親のほうに「中身のないメソッド」を置きます。これを抽象メソッドと呼びます。中身がないので、子が必ず書くことになります。書き忘れるとコンパイルエラーで気づけます。

## まず押さえること

抽象メソッドは、名前だけあって中身（`{ }` の処理）がありません。かわりに `abstract` を付け、行末をセミコロンで終えます。抽象メソッドを1つでも持つクラスには、クラス側にも `abstract` を付けます。これが抽象クラスです。

抽象クラスは `new` で直接作れません。子クラスを作り、抽象メソッドの中身を書いてから使います。

```
abstract class Drink {
    void info() { System.out.println("飲み物です"); }   // 中身あり。ふつうのメソッド
    abstract void serve();                              // 中身なし。子が必ず書く
}
```

`info()` のように中身のあるメソッドと、`serve()` のように中身のない抽象メソッドは、同じ親に同居できます。共通の処理は親に書き、子ごとに変えたい処理だけ抽象メソッドにします。

`@Override` は前回と同じで、子が親のメソッドを実装したことを示す目印です。

## ステップ1: 予測写経

次のお手本を1行ずつ写します。写す前に「何が表示されるか」を予測します。`info` と `serve` がどの順で何を出すかに注目してください。写し終えたら実行し、予測と合っているか確かめます。

保存先は `src/main/java/com/example/week06/03_40m_抽象クラス/DrinkDemo.java` です。同じファイルに3つのクラスを書きます。

```java
public class DrinkDemo {
    public static void main(String[] args) {
        Coffee c = new Coffee();
        c.name = "コーヒー";
        c.info();
        c.serve();
    }
}

abstract class Drink {
    String name;

    void info() {
        System.out.println(name + "です");
    }

    abstract void serve();
}

class Coffee extends Drink {
    @Override
    void serve() {
        System.out.println(name + "を熱いカップで出します");
    }
}
```

実行は `java src/main/java/com/example/week06/03_40m_抽象クラス/DrinkDemo.java` です。

## ステップ2: 暗写（設計メモから組み立てる）

お手本のコードは閉じます。次の設計メモだけを手がかりに、`DrinkDemo` を書きます。丸暗記ではなく、設計をコードへ起こす練習です。書けたら実行し、同じ出力になるか確かめます。

- `Drink` クラス（親、`abstract` を付ける）
  - フィールド … name（String）
  - `info()` … 中身あり。`コーヒーです` のように name を表示する
  - `serve()` … 抽象メソッド。中身なしで `abstract void serve();` と書く
- `Coffee` クラス（子、`Drink` を継承）
  - `serve()` … 抽象メソッドを実装する。`コーヒーを熱いカップで出します` と表示する。`@Override` を付ける
- 実行用クラス `DrinkDemo`
  - `main` で Coffee を作り、name に "コーヒー" を入れる
  - `info()` を呼び、続けて `serve()` を呼ぶ
