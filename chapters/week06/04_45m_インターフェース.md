# Week 6 インターフェース（できることを約束する）

前回は抽象クラスをやりました。中身のないメソッドを親へ置き、子に実装させました。インターフェースも似た働きをします。違いは、中身のある処理やフィールドを持たない点です。「このクラスは何ができるか」の一覧だけを決めます。

## まず押さえること

インターフェースは `interface` で作ります。中に書くのはメソッドの名前だけです。全部が中身なしなので、`abstract` は書きません。

```
interface Switchable {
    void turnOn();     // 中身なし。abstract は書かない
    void turnOff();
}
```

使う側は `implements` を書きます。`extends` ではありません。「約束を守ります」という意味です。約束したメソッドを1つでも書き忘れると、コンパイルエラーになります。

実装するメソッドには `public` が要ります。ここが抽象クラスと違うところです。前回の `serve()` には `public` を書きませんでしたが、今回は必要です。付け忘れると、やはりコンパイルエラーになります。

インターフェースはフィールドを持てません。だから name は実装するクラス側に置きます。前回は name を親へ置きましたが、今回は逆になります。

使い分けはこうです。共通のフィールドや中身のある処理を親へ置きたいときは、抽象クラスを選びます。できることだけを決めたいときは、インターフェースを選びます。

## ステップ1: 予測写経

次のお手本を1行ずつ写します。写す前に「何が表示されるか」を予測します。写し終えたら実行し、予測と合っているか確かめます。

保存先は `src/main/java/com/example/week06/04_45m_インターフェース/LightDemo.java` です。同じファイルに3つ書きます。クラスが2つと、インターフェースが1つです。

```java
public class LightDemo {
    public static void main(String[] args) {
        Lamp lamp = new Lamp();
        lamp.name = "デスクライト";
        lamp.turnOn();
        lamp.turnOff();
    }
}

interface Switchable {
    void turnOn();
    void turnOff();
}

class Lamp implements Switchable {
    String name;

    @Override
    public void turnOn() {
        System.out.println(name + "を点けます");
    }

    @Override
    public void turnOff() {
        System.out.println(name + "を消します");
    }
}
```

実行は `java src/main/java/com/example/week06/04_45m_インターフェース/LightDemo.java` です。

## ステップ2: 暗写（設計メモから組み立てる）

お手本のコードは閉じます。次の設計メモだけを手がかりに、`LightDemo` を書きます。丸暗記ではなく、設計をコードへ起こす練習です。書けたら実行し、同じ出力になるか確かめます。

- `Switchable` インターフェース
  - `turnOn()` … 中身なし。名前とセミコロンだけ
  - `turnOff()` … 中身なし
- `Lamp` クラス（`Switchable` を実装する）
  - フィールド … name（String）
  - `turnOn()` … `デスクライトを点けます` のように name を使って表示する。`public` と `@Override` を付ける
  - `turnOff()` … `デスクライトを消します` のように表示する。同じく `public` と `@Override` を付ける
- 実行用クラス `LightDemo`
  - `main` で Lamp を作り、name に "デスクライト" を入れる
  - `turnOn()` を呼び、続けて `turnOff()` を呼ぶ
